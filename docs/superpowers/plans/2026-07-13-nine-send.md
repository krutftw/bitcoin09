# Nine Send Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a bounded, client-side-encrypted send service and installable mobile/desktop web interface at `https://btc09.org/send/`.

**Architecture:** A new Go `ninesend` package owns opaque drop persistence and an HTTP API. Static, dependency-free PWA assets encrypt and decrypt a versioned envelope with Web Crypto; only ciphertext reaches the relay, while the AES key remains in the URL fragment. The existing `btc09` binary gains a loopback-only relay command, with isolated systemd/nginx deployment and small links from the website and desktop wallet.

**Tech Stack:** Go 1.25 standard library, browser Web Crypto AES-256-GCM, HTML/CSS/ES modules, Node `node:test`, nginx, systemd, Cloudflare.

## Global Constraints

- No accounts, advertisements, analytics, trackers, third-party scripts, or requirement to own 09C.
- Plaintext item limit is 20 MiB; maximum expiry is 24 hours; maximum successful fetches is five; total relay storage cap is 2 GiB.
- The relay binds only to numeric loopback and stores only opaque ciphertext plus operational metadata.
- The decryption key exists only in the URL fragment and is never accepted by an API endpoint.
- Visible copy is plain English, human-sounding, and does not claim scanning or guarantees the service does not provide.
- Existing node, wallet, explorer, gateway, OTC, website, and Discord behavior must remain available.
