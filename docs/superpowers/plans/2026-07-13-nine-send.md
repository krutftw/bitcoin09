# Nine Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an accountless, client-side-encrypted send-to-self inbox at `https://btc09.org/inbox/` for text, links, photos, and small documents across a person's devices.

**Architecture:** A Go `nineinbox` package stores opaque encrypted inbox items behind hashed mailbox credentials. A dependency-free PWA generates pairing secrets and encrypts versioned envelopes with Web Crypto; its QR fragment carries secrets that never appear in the initial request. The existing `btc09` binary gains a loopback-only relay command, with isolated nginx/systemd deployment and restrained links from the website and wallet.

**Tech Stack:** Go 1.25 standard library, browser Web Crypto AES-256-GCM, IndexedDB, HTML/CSS/ES modules, Node `node:test`, nginx, systemd, Cloudflare.

## Global Constraints

- No ecosystem or Nine account, advertisements, analytics, trackers, third-party scripts, or requirement to own 09C.
- Item limit is 20 MiB; inbox limit is 50 MiB and 200 items; file expiry is at most seven days; pinned text/link expiry is at most 30 days; total relay storage is 2 GiB.
- The relay binds only to numeric loopback and stores ciphertext plus operational metadata, never the AES key.
- Pairing secrets exist only in URL fragments, QR payloads, IndexedDB, and explicit encrypted recovery exports.
- Clipboard collection is always manual and opt-in; version one makes no background or push-delivery promise.
- Visible copy is plain English and does not claim scanning, anonymity, or guarantees the service does not provide.
- Existing node, wallet, explorer, gateway, OTC, website, and Discord behavior must remain available.
